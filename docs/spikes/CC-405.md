# CC-405 — memory card frontmatter standardization + /mem-doctor (design spike result)

**Status**: complete
**Date**: 2026-06-23
**Ticket**: BACKLOG.md CC-405

> Note on epic: CC-405 carries the `retrieval` epic (impl ticket), not the
> `spike` epic. This design spike was run to settle 4 blocking schema /
> integration decisions before an implementation brief is written. Its product
> is the decisions below, not code.

## Investigation scope

Four durable decisions had to be settled before an impl spec could be written:

1. **additive vs replace** — do the new card frontmatter fields
   (`topics`/`priority`/`status`/`updated_at`/optional `expires_at`/`repo_refs`)
   stack additively on top of the existing `name`/`description`/`metadata.*`
   frontmatter, or replace the `metadata` block?
2. **warn→enforce gating point** — where does validation hook in: a warn-only
   reporter, or also enforce at write time in `/mem-distill` + `/memory-compress`?
3. **repo_refs staleness ref syntax** — what machine-checkable string syntax for
   a file path / function / flag lets the health check detect a stale ref?
4. **/mem-doctor output schema** — the standard report format, and whether the
   surface is a `/mem-doctor` slash command or a `pmctl memory doctor` subcommand.

A Pilot walkthrough (this is an API-design spike) on a real live card is required
to prove the additive decision is clean.

## Angles

### a1 — Consumer audit (additive vs replace) + Pilot

Audited every actual consumer of the existing frontmatter to ground the decision
in real coupling rather than preference:

| Consumer | Reads/writes | New top-level keys | Remove `metadata` block |
| --- | --- | --- | --- |
| Claude memory-graph tool (external/opaque) | `name`/`description`/`metadata.{node_type,type,originSessionId}` | no break (YAML ignores unknown keys) | **BREAKS** — `node_type:memory` is the node tag; `type` distinguishes feedback/project/reference; `originSessionId` is provenance |
| `/memory-compress` (L61, L108) | reads `name:`/`description:`/`metadata.type:` | no break (L61 is a prose note, not a validator) | partial break — merge-by-type degrades, no crash |
| `/mem-distill` (L159-160) | writes `description:`; builds new cards in "standard frontmatter format" | no break | low risk |
| `/mem-recall` | reads `episodes.jsonl` only | N/A | N/A |
| `/mem-search` | full-text grep, no frontmatter parse | no break | no break |
| `/mem-log` | writes episodes only | N/A | N/A |
| `pmctl-context.sh` `_ctx_index_file` (L405-454) | path/lang/mtime/sha1/size; heading-based chunking; frontmatter is lead text, not key-parsed | no break | no break |
| `pmctl-context.sh` `_ctx_memory_trust` (L53-58) | **pure path-based** (`*episodes*.jsonl`→medium, else→high) | no break | no break |
| `find_memory_dir` / `memory.sh` | path walk only, never opens cards | N/A | N/A |

**Finding**: the decision is forced by three consumers — (1) the external Claude
memory-graph node tag `metadata.node_type`, (2) `/memory-compress` L61 reading
`metadata.type`, (3) `/mem-distill` "standard frontmatter format" for new cards.
New fields append as top-level YAML after the `metadata` block; `name`,
`description`, `metadata.*` stay byte-identical.

### a2 — warn→enforce gating + repo_refs grammar

**Write sites.** `/mem-distill` Step 6: D1 add new card file, D2 add MEMORY.md
index line, D3 update hook text, D4 update `description:` on linked card.
`/memory-compress` Step 6: C1 backup, C2 overwrite MEMORY.md, C3 update merged
card `description:`, C4 rename redundant → `.archived`.

**Warn phase** (the read-only reporter, manual, non-blocking): reads only
frontmatter blocks + MEMORY.md index lines (does not pull all cards into
conversation). WARN on missing required field or stale `repo_ref`; INFO on entry
count/bytes, unreferenced card, duplicate hook, episodes size. Does **not** exit
non-zero. Required fields: `topics`/`priority`/`status`/`updated_at`/`repo_refs`
(`repo_refs` may be empty `[]`).

**Enforce phase** (after the migration trigger): D1 **block** — reject a new card
missing required frontmatter. D4 **auto-fill** missing fields
(`status: active`, `updated_at: <today>`) rather than block; WARN on stale ref.
C2 report WARN in summary, no block. C3 auto-fill `updated_at` like D4.
D2/D3/C1/C4 are out of enforce scope.

**Migration trigger**: when the reporter yields zero WARN (INFO only) across all
existing cards → flip to enforce. Steps: warn-scan → backfill (optionally
`/mem-distill --backfill-frontmatter`) → confirm clean → add enforce logic to
`mem-distill` + `memory-compress` Step 6.

**repo_refs grammar.**

| Kind | Syntax | Verify | Stale when |
| --- | --- | --- | --- |
| file | `path:<repo-root-relative>` (no leading `/`) | `test -f "$REPO_ROOT/$path"` | path absent |
| symbol | `fn:<rel-path>#<symbol>` | `grep -qE "^<symbol>\(\)\|^function <symbol>" file` | file missing OR symbol def not found |
| flag | `flag:<invocation> <--flag-token>` | `grep -qrF -- "<--token>" scripts/` (or the specific script) | token absent |

Validated against real cards: `path:agents/project-pm.md` → fresh;
`fn:scripts/lib/guard-framework.sh#g_audit` → fresh, `#hk_audit` → **stale**
(CC-384 rename); `flag:pmctl context index --source` → fresh;
`path:scripts/hook-codex-bash-guard.sh` → **stale** (CC-395 deleted). Dispatch in
the doctor loop uses `kind=${ref%%:*}`, `rest=${ref#*:}`.

### a3 — surface + report schema

**Surface verdict**: `pmctl memory doctor` (a `memory/doctor` dispatch case),
**not** a slash command. Evidence:

- `pmctl-context.sh` is the closest precedent: lib → `cli/pmctl` source loop
  (L19) → `case "$cmd/$sub"` dispatch (L66-118).
- `find_memory_dir` lives in `scripts/lib/memory.sh` and is already
  test-fixture-covered (CC-403 / CC-411). The `mem-*` slash commands each
  re-implement the find-memory-dir walk in ad-hoc bash/python (`mem-distill`
  L29-37, `mem-recall` L27-43) **because executor prose cannot call repo shell
  libs** — duplicated, unversioned, untestable.
- Testability: a deterministic subcommand lets qa-tester assert via `grep`/`jq`
  + stable exit codes (0 healthy, 1 issues, 2 usage); prose requires parsing
  natural language.
- Plan: new `scripts/lib/pmctl-memory.sh` with `pmctl_memory_doctor()`, add
  `pmctl-memory` to the source loop, add a `memory/doctor` case.

**Frozen report schema** (ordered): `memory_dir`(str), `entry_count`(int),
`memory_bytes`(int), `episodes_bytes`(int, 0 if absent), `dead_links`(list<str>:
MEMORY.md link → missing file), `orphan_cards`(list<str>: file present but
unreferenced, excl MEMORY.md), `duplicate_hooks`(list<str>: hook text ≥2×),
`stale_repo_refs`(list<{card,ref}>, uses a2's grammar — dependency satisfied so
the field is fully specified, not null), `issues_count`(int).
Flags: `pmctl memory doctor [--json] [--repo-root <path>]`. Human-text
label-aligned output + `--json` carrying `schema_version: 1`. Exit 1 iff
`issues_count > 0`.

## Findings

- additive-vs-replace is **forced** (not preference): the external memory-graph
  node tag, `/memory-compress` metadata.type read, and `/mem-distill` card
  format all depend on the `metadata` block surviving. No consumer breaks on
  appended unknown top-level keys (YAML-standard).
- The reporter (a3's `pmctl memory doctor` warn mode) **is** a2's warn-phase
  reporter — the two angles are consistent: the read-only subcommand reports;
  the separate enforce logic lives in `mem-distill`/`memory-compress` Step 6
  prose.
- a2's repo_refs grammar fully populates a3's `stale_repo_refs` field — the
  cross-angle dependency is closed, not left null.

## Recommendation

| # | Decision | Verdict | Outcome |
| --- | --- | --- | --- |
| 1 | additive vs replace | **GREEN** (one AMBER caveat) | **Adopt additive.** New fields append as top-level YAML after `metadata`; `name`/`description`/`metadata.*` untouched. Removing/renaming the `metadata` block is forbidden. AMBER caveat: the external Claude memory-graph tool is opaque, so the *removal-prohibition rationale* rests on a conservative (low-risk, YAML-standard) assumption it won't break on appended keys — cannot be empirically grep-proven. |
| 2 | warn→enforce gating | **GREEN** | **Adopt staged plan.** Warn-only reporter first; enforce added to `mem-distill`/`memory-compress` Step 6 only after a clean warn-scan (zero WARN). D1 blocks; D4/C3 auto-fill; C2 warns. |
| 3 | repo_refs ref syntax | **GREEN** | **Adopt the `path:`/`fn:`/`flag:` grammar** with the per-kind verify commands above. Validated against real fresh + real stale refs. |
| 4 | /mem-doctor surface + schema | **GREEN** | **Adopt `pmctl memory doctor`** (lib-dispatch, not a slash command) with the frozen ordered schema + `--json schema_version: 1` + exit-code contract. |

## Pilot walkthrough

Representative consumer: the real live card
`feedback_development_workflow.md` under the memory dir. Applying every spike
decision (additive append; enum-correct `priority`; `repo_refs` grammar).

**Before**
```yaml
---
name: development-workflow
description: 所有開發與規劃均直接在主線程完成；只有 pr-gate 需要使用 codex
metadata: 
  node_type: memory
  type: feedback
  originSessionId: 787ad6e4-a40e-43f4-8a29-c5a6c0ee85f7
---
```

**After (additive)**
```yaml
---
name: development-workflow
description: 所有開發與規劃均直接在主線程完成；只有 pr-gate 需要使用 codex
metadata: 
  node_type: memory
  type: feedback
  originSessionId: 787ad6e4-a40e-43f4-8a29-c5a6c0ee85f7
topics:
  - workflow
  - dispatch
  - executor
priority: normal
status: active
updated_at: "2026-06-23"
repo_refs:
  - flag:pmctl gate run --executor codex
---
```

**Proof of cleanliness**:
- `name` / `description` / `metadata.*` are byte-identical — no memory-graph
  consumer (a1) is touched.
- 6 fields appended as top-level YAML; no key collision with `metadata`.
- `priority: normal` — uses the ticket enum `always/normal/low`. (The angle draft
  used `priority: high`, which is **not** a valid enum value; corrected here.)
- `repo_refs` populated with a real, verifiable flag ref via a2's grammar
  (`flag:` → `grep -qrF -- "--executor" scripts/` → fresh).
- The whole block stays within the `pmctl-context` ~2000-char first-chunk limit.

The walkthrough applies cleanly, so the API decisions are mature enough to ship.

## Open risks

- **External memory-graph opacity (AMBER on decision 1).** The Claude
  memory-graph tool is a closed platform consumer; the additive verdict's
  removal-prohibition assumes appended top-level keys are ignored. This is
  YAML-standard and low-risk but cannot be grep-proven. Mitigation: never remove
  the `metadata` block; spot-check one card after the first migration.
- **`fn:` grammar precision.** The symbol verify regex matches `name()` /
  `function name` shell definitions; it would miss other definition styles. Scope
  repo_refs `fn:` to shell symbols for now, or extend the regex per language.
- **enforce flip timing.** The migration trigger (zero WARN) depends on a
  backfill pass landing first; sequence the backfill before any enforce logic to
  avoid blocking legitimate writes.
