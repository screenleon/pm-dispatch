### 2.2 `configurable?` verdicts (1-line each)

- **sandbox** -> yes-with-guard. Today only `workspace-write` and `read-only` accepted on bash route. Adding e.g. `danger-full-access` requires (a) lift the bash-route reject in validate.sh:219 with explicit override-channel design, (b) thread through codex-dispatch.sh:66 default, (c) PM template literal updates. Not recommended as a config knob -- the reject is a security invariant, not a default.
- **approval** -> **no**. The `never`-only invariant on bash route is load-bearing for the unattended-dispatch model. Any "configurability" would invert the threat model -- keep the validator reject; surface alt approvals only via Agent fallback route.
- **timeout** -> yes. Env layer already exists; brief field overrides; validator bounds (30-3600) already prevent abuse. **Phase 3 / impl scope**: promote `CODEX_DISPATCH_TIMEOUT` to documented public env (currently undocumented in dispatch-brief.md env list) and optionally add `~/.pm-dispatch/config` fallback below env. Validator shape change: none needed.
- **model alias** -> yes-with-guard. The codex-dispatch.sh:127-131 map is the **single source of truth in code** but dispatch-brief.md:264-271 is the **PM-facing SoT** with a manual "keep in sync" warning -- classic dual-write smell. **Impl path**: move map to `share/model-aliases.tsv` (or equivalent), have both codex-dispatch.sh and a doc-render step read from it, add `make lint-model-aliases` to CI mirroring the `lint-backlog-render` pattern from `[[feedback_japanese_site_backlog_render]]`.

### 2.3 Timeout-axis PoC outline (lowest-risk first axis to address in CC-060 impl)

**Why timeout first**: only axis where (a) indirection already partially exists, (b) no security invariant is at stake, (c) validator already enforces bounds, (d) per-machine variation is most likely needed.

**Proposed precedence chain** (highest wins):
1. Brief metadata `timeout: <int>` (already wins today via handover-validate)
2. Env `CODEX_DISPATCH_TIMEOUT` (already works at codex-dispatch.sh:69)
3. New: `~/.pm-dispatch/config` key `dispatch.default_timeout` (optional file, NOT created by installer)
4. Hardcoded fallback `1200` (preserved; codex-dispatch.sh:69 keeps current literal as ultimate floor)

**Changes required**:
- `scripts/codex-dispatch.sh:69` -> wrap fallback in a tiny `_load_config_timeout()` helper that sources `~/.pm-dispatch/config` if present and exports `PM_DISPATCH_DEFAULT_TIMEOUT` (still subject to `CODEX_DISPATCH_TIMEOUT` env winning above it).
- `docs/dispatch-brief.md` -> add an "Env / config precedence" subsection under existing timeout discussion (~line 218).
- `scripts/test-codex-dispatch.sh` -> add 3 fixtures: env-only, config-only, brief-wins-over-both.
- Validator: **no change** -- already bounded.
- Hook: **no change** -- not a gatekeeper here.

**Out of CC-060 scope** (push to followups):
- sandbox/approval -- invariants, not knobs; do NOT bundle into CC-060.
- ~~Same pattern applied to model~~ -- **NOW IN SCOPE** per Q1:B decision (see §2.5).
