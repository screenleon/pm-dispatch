# CC-422 — adapter 共用 dispatch 初始化邏輯抽 lib (spike result)

**Status**: complete
**Date**: 2026-06-30
**Ticket**: BACKLOG.md CC-422

## Investigation scope

分析 `adapters/claude/dispatch.sh`（330 行）、`adapters/codex/dispatch.sh`（412 行）、
`adapters/opencode/dispatch.sh`（467 行）三個 adapter 的 dispatch 初始化邏輯，識別：

1. 可安全共用的部分（純 setup）
2. 必須保持 per-adapter 的部分（isolation 翻譯、native flag、run invocation）
3. 若要抽出 `scripts/lib/dispatch-common.sh`，其函式介面應如何設計

## Angles

### Angle 1 — Self-snapshot block

三個 adapter 都有相同的 self-snapshot 邏輯（re-exec from `/tmp` copy）。

**共同部分**：複製 shared lib 到 snapshot dir 的程式碼在三個 adapter 幾乎相同：
```bash
mkdir -p -- "$snapshot_dir/lib"
cp -- "$repo/scripts/lib/state-writer.sh"  "$snapshot_dir/lib/state-writer.sh"  || true
cp -- "$repo/scripts/lib/state-paths.sh"   "$snapshot_dir/lib/state-paths.sh"   || true
cp -- "$repo/scripts/lib/portable.sh"      "$snapshot_dir/lib/portable.sh"      || true
cp -- "$repo/scripts/lib/model-aliases.sh" "$snapshot_dir/lib/model-aliases.sh" || true
cp -- "$repo/scripts/lib/timeout-resolve.sh" "$snapshot_dir/lib/timeout-resolve.sh" || true
```

**不可共用的部分**（必須 per-adapter）：
- trigger regex（每個 adapter 的 snapshot dir name pattern 不同）
- mktemp pattern name（`claude-dispatch.XXXXXX` vs `codex-dispatch.XXXXXX` vs `opencode-dispatch.XXXXXX`）
- adapter-specific 文件複製（isolation-map.yaml 路徑各異；opencode 多一個 adapter.yaml）
- `exec "$snapshot" "$@"` 必須在 script 本體，無法外包

**結論**：lib-copy 部分可抽成 `dc_snapshot_copy_libs <snapshot_dir> <repo_root>` helper，
但 trigger + re-exec 邏輯必須留 per-adapter。

### Angle 2 — Arg validation

三個 adapter 的 arg 驗證邏輯幾乎相同，差異只有 codex 多一個 `--brief-file` 與 `-- brief...` 互斥檢查。

共同驗證：
```
--cd <dir>      present + is-a-directory
--brief-file    present + readable + BRIEF="$(<$BRIEF_FILE)"
$BRIEF          non-empty (unless --print-cmd)
$TIMEOUT        non-negative integer regex
```

**可抽函式**：`dc_validate_args <work_dir> <brief_file> <brief_ref> <timeout> <print_cmd>`
→ 設 `DC_BRIEF`（讀取結果）並在驗證失敗時 return 非零。

codex 的 inline `--` brief form 為 edge case，可保留 per-adapter；`dc_validate_args` 僅涵蓋 file-based path。

### Angle 3 — Trace dir setup

三個 adapter 的 trace dir 設定邏輯**完全相同**，差異只有 adapter prefix：

```bash
if ! declare -F sw_resolve_trace_dir >/dev/null 2>&1; then
  echo "Error: trace-path helper unavailable" >&2; exit 2
fi
TRACE_DIR="$(sw_resolve_trace_dir "$TRACE_DIR_OVERRIDE" "$WORK_DIR/.agent-trace")" || exit 2
mkdir -p "$TRACE_DIR"
TRACE="$TRACE_DIR/<prefix>-$TS.jsonl"
LAST="$TRACE_DIR/<prefix>-$TS.last"
STDERR_LOG="$TRACE_DIR/<prefix>-$TS.stderr"
```

**可抽函式**：`dc_setup_trace_dir <override> <work_dir> <adapter_prefix> <ts>`
→ 設 `DC_TRACE_DIR`, `DC_TRACE`, `DC_LAST`, `DC_STDERR_LOG`

### Angle 4 — `_refresh_latest_pointers`

三個 adapter 完全相同的 4 行 `ln -sfn` 邏輯，差異只有 prefix。

**可抽函式**：`dc_refresh_latest_pointers <adapter_prefix> <trace_dir> <ts>`

### Angle 5 — Output footer

三個 adapter 結尾的 footer block 幾乎**完全相同**：
```bash
echo "---"
echo "trace:  $TRACE"
echo "last:   $LAST"
echo "stderr: $STDERR_LOG"
echo "exit:   $EXIT"
echo "model:  $MODEL"
echo "---"
if [[ -s "$LAST" ]]; then echo "=== final message ==="; cat "$LAST"; fi
exit $EXIT
```

（opencode 用 `${USED_MODEL:-<none>}` 而非 `$MODEL`，但結構相同。）

**可抽函式**：`dc_print_footer <trace> <last> <stderr_log> <exit> <model>`

### Angle 6 — Isolation resolution（不可共用）

三個 adapter 的 isolation 翻譯完全不同：
- claude: YAML key `permission_mode` → `--permission-mode <value>`
- codex: YAML key `sandbox` + `config_overrides[]` → `--sandbox` + multiple `-c` flags
- opencode: YAML key `native_flags[]` → 直接附加到 `_CMD`

不只 YAML schema 不同，翻譯結果的類型也不同（string vs array）。**必須保持 per-adapter。**

### Angle 7 — Model resolution（不可共用）

三個 adapter 各用不同的 TSV 文件與不同的 `ma_resolve_alias` 變體：
- claude: `claude-model-aliases.tsv` + `ma_resolve_alias`（lenient）
- codex: `model-aliases.tsv` + `ma_resolve_alias_strict`（strict）+ effort tracking
- opencode: `opencode-model-aliases.tsv` + `ma_resolve_alias`（lenient）+ fallback_chain loop

**必須保持 per-adapter。**

### Angle 8 — CMD construction、run invocation、token logging（不可共用）

- CMD 構建：claude 用 `claude -p --permission-mode ...`；codex 用 `codex exec --sandbox ...`；opencode 用 `opencode run --dir ...`（brief 為 CLI arg，非 stdin）
- Run: stdin 傳遞 vs CLI arg，timeout 處理方式各異，opencode 有 fallback loop
- Token logging: 各有不同的 JSONL event type（`result` vs `turn.completed` vs 無）

**全部必須保持 per-adapter。**

## Findings

### 可安全共用的區塊（共 ~60 行重複，每 adapter ~20 行）

| 函式 | 涵蓋邏輯 | 估計行數（lib） |
|---|---|---|
| `dc_snapshot_copy_libs` | shared lib 文件複製到 snapshot dir | ~10 行 |
| `dc_validate_args` | work_dir + brief_file + brief + timeout 驗證 | ~20 行 |
| `dc_setup_trace_dir` | trace dir 解析 + mkdir + TRACE/LAST/STDERR_LOG 路徑 | ~15 行 |
| `dc_refresh_latest_pointers` | `ln -sfn` latest.* 更新 | ~8 行 |
| `dc_print_footer` | footer echo block + cat $LAST + exit | ~12 行 |

**合計**：`dispatch-common.sh` 約 65 行；從三個 adapter 移除約 ~60 行重複 ×3 = 節省 ~120 行。

### 不可共用的區塊

| 區塊 | 原因 |
|---|---|
| Self-snapshot trigger + re-exec | per-adapter regex + 文件清單 + exec 必須在 script 本體 |
| Isolation resolution | schema 完全不同（permission_mode vs sandbox/config_overrides vs native_flags） |
| Model resolution | 不同 TSV、strict vs lenient、effort、fallback chain |
| CMD 構建 | 完全不同的 CLI |
| Run invocation | stdin vs arg；fallback loop（opencode 獨有） |
| Banner 欄位 | claude 有 permission；codex 有 sandbox/approval；opencode 有 fallback chain |
| Token logging | 不同 JSONL event type，opencode 無 |

### Snapshot block 的特殊限制

self-snapshot re-exec 的設計決定了 lib 函式**無法在 snapshot trigger 之前**被 source，
因為 `$SCRIPT_DIR/lib/` 在 snapshot 前尚未被建立。`dc_snapshot_copy_libs` 只能是一個輔助
腳本，被 source 後**在 snapshot block 內部**呼叫，不能取代 trigger + re-exec 本體。

## Recommendation

**Adopt（有限範圍）**。

抽取下列 5 個函式到 `scripts/lib/dispatch-common.sh`：

```
dc_snapshot_copy_libs <snapshot_dir> <repo_root>
dc_validate_args      <work_dir> <brief_file> <print_cmd> <timeout>  → sets DC_BRIEF
dc_setup_trace_dir    <override> <work_dir> <prefix> <ts>            → sets DC_TRACE_DIR/DC_TRACE/DC_LAST/DC_STDERR_LOG
dc_refresh_latest_pointers <prefix> <trace_dir> <ts>
dc_print_footer       <trace> <last> <stderr_log> <exit> <model>
```

同時需要 `test-dispatch-common.sh` 測試這 5 個函式的行為。

**明確不抽取**的部分：isolation 翻譯、model 解析、CMD 構建、run invocation、banner、token logging。

### 介面設計約束

1. `dispatch-common.sh` 不得 `set -euo pipefail`（被 source 進已設 flag 的 adapter script 中；flag 繼承）。
2. 所有輸出透過命名變數（`DC_*` prefix）返回，避免 subshell 捕捉（影響 `set -e` 傳播）。
3. Snapshot block 中 source `dispatch-common.sh` 前必先確認 `$SCRIPT_DIR/lib/dispatch-common.sh` 已複製，否則 snapshot re-exec 後找不到 lib。需在 self-snapshot block 加入：
   ```bash
   [[ -r "$repo/scripts/lib/dispatch-common.sh" ]] && \
     cp -- "$repo/scripts/lib/dispatch-common.sh" "$snapshot_dir/lib/dispatch-common.sh" || true
   ```

## Open risks

1. **Snapshot lib 複製一致性**：三個 adapter 各自維護 lib 複製清單；新增 lib 時可能漏複製某個 adapter。`dispatch-common.sh` 被加入後，若有人在 adapter 的 snapshot block 忘記加 cp 行，snapshot re-exec 會 `source` 失敗。`dc_snapshot_copy_libs` 本身應解決這問題（集中清單），但需要所有三個 adapter 的 snapshot block 都改為呼叫 `dc_snapshot_copy_libs`——這部分是 self-snapshot trigger 之前的修改，需要仔細驗證。

2. **Banner 無法共用**：三個 adapter 的開場 banner 欄位差異大，不嘗試共用（避免過度參數化）。

3. **opencode `$LAST` 寫入時機**：opencode 的 `.last` 提取在 fallback loop 結束後，邏輯比 claude/codex 複雜；`dc_print_footer` 只做 print，不影響此邏輯。

## Pilot walkthrough

以 `adapters/claude/dispatch.sh` 為 pilot consumer，展示 before/after：

**Before（inline 邏輯，約 30 行）**：

```bash
# arg validation — inline
if [[ -z "$WORK_DIR" ]]; then
  echo "Error: --cd <dir> is required" >&2; exit 2
fi
if [[ ! -d "$WORK_DIR" ]]; then
  echo "Error: working dir not found: $WORK_DIR" >&2; exit 2
fi
if [[ -n "$BRIEF_FILE" ]]; then
  if [[ ! -f "$BRIEF_FILE" || ! -r "$BRIEF_FILE" ]]; then
    echo "Error: brief file not found or not readable: $BRIEF_FILE" >&2; exit 2
  fi
  BRIEF="$(<"$BRIEF_FILE")"
fi
if [[ -z "$BRIEF" && "$PRINT_CMD" -ne 1 ]]; then
  echo "Error: brief is required; pass --brief-file <path>" >&2; exit 2
fi
if ! [[ "$TIMEOUT" =~ ^[0-9]+$ ]]; then
  echo "Error: --timeout must be a non-negative integer (got: $TIMEOUT)" >&2; exit 2
fi

# trace setup — inline
if ! declare -F sw_resolve_trace_dir >/dev/null 2>&1; then
  echo "Error: trace-path helper unavailable (state-paths.sh not loaded)" >&2; exit 2
fi
TRACE_DIR="$(sw_resolve_trace_dir "$TRACE_DIR_OVERRIDE" "$WORK_DIR/.agent-trace")" || exit 2
mkdir -p "$TRACE_DIR"
TRACE="$TRACE_DIR/claude-$TS.jsonl"
LAST="$TRACE_DIR/claude-$TS.last"
STDERR_LOG="$TRACE_DIR/claude-$TS.stderr"
```

**After（shared lib）**：

```bash
# shellcheck disable=SC1091
. "$SCRIPT_DIR/lib/dispatch-common.sh"

dc_validate_args "$WORK_DIR" "$BRIEF_FILE" "$PRINT_CMD" "$TIMEOUT" || exit 2
BRIEF="$DC_BRIEF"

if [[ "$PRINT_CMD" -ne 1 ]]; then
  dc_setup_trace_dir "$TRACE_DIR_OVERRIDE" "$WORK_DIR" "claude" "$TS" || exit 2
  TRACE_DIR="$DC_TRACE_DIR"; TRACE="$DC_TRACE"; LAST="$DC_LAST"; STDERR_LOG="$DC_STDERR_LOG"
fi
```

diff 乾淨：無 shim，無殘留 inline 驗證，無行為變化。`_refresh_latest_pointers` 函式體替換為 `dc_refresh_latest_pointers "claude" "$TRACE_DIR" "$TS"`；footer 區塊替換為 `dc_print_footer "$TRACE" "$LAST" "$STDERR_LOG" "$EXIT" "$MODEL"`。
