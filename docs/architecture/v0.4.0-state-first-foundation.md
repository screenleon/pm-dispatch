# v0.4.0 foundation scoping — state-first substrate (single-writer)

**Status**: scoping / pre-implementation design. Not a commitment to dates.
**Decision**: CC-211 **committed (2026-06-03)** — state-first foundation is the v0.4.0 headline.
First consumer = `pmctl trace`; `routing_log.md` machine-writes deprecated. See `DECISIONS.md`
2026-06-03 and §9 (resolved). The maintainer explicitly accepts low short-term user-visible
payoff (small current user base → substrate correctness outranks shipping features).
**Authored**: 2026-06-03, after v0.3.0 shipped. Synthesises two independent brainstorms
(Claude main-thread + a read-only codex pass) that both landed on "commit state-first, build
the foundation first, thin-slice it, defer MCP and the capability layer."

---

## 1. Purpose & scope

v0.3.0 shipped the **spine** (schema + `pmctl` runtime + thin adapters). It is schema-first and
adapter-thin, but **only partially state-first**. This foundation makes the substrate *truthful*:
machine state is written through **one** writer (`pmctl`), as JSONL, with the markdown/JSONL split
the architecture already specifies.

**In scope (the foundation):**
- A single-writer contract: `pmctl` is the sole producer of machine state.
- An actually-wired **event stream** (`events.jsonl`) for the dispatch/guard/route paths.
- Re-routing today's direct writers through `pmctl`.
- A thin vertical slice that proves the contract end-to-end before broad rollout.

**Explicitly NOT in scope here** (later in v0.4.0 or beyond): the capability layer
(CC-234 event-derived memory, CC-237 context-enricher), the MCP bridge (CC-216), and
`adapters/antigravity|opencode`. See §8.

## 2. As-built state map (grounded)

What actually writes machine state today:

| Entity | Schema | Writer fn (`scripts/lib/state-writer.sh`) | Wired in production? | Notes |
|---|---|---|---|---|
| **Run** | `core/schema/run.schema.json` | `runs_append` via `sw_append_dispatch_run` (state-writer.sh:160) | **Yes** — but called **by the adapters** (`adapters/codex/dispatch.sh:369`, claude equivalent) | This is the single-writer violation: the *adapter* is the writer, not `pmctl`. |
| **Event** | `core/schema/event.schema.json` (kinds: `task.*`/`run.*`/`review.*`/`guard.*`/`decision.recorded`) | `events_append` (state-writer.sh:123) | **No** — function exists, **no production caller** | Event stream is defined but unwired; `sw_append_dispatch_run` writes Run only, emits no event. |
| **Task** | `core/schema/task.schema.json` | `task_upsert` (state-writer.sh:195) | **No** — defined, no production caller | FSM in `core/policy/task-states.yaml`. |
| **Review** | `core/schema/review.schema.json` | — none | No | Gate writes results as markdown in `.gate-results/`, not as Review state. |
| **Decision** | `core/schema/decision.schema.json` | — none | No | `DECISIONS.md` is human-authored markdown (correct); no machine Decision rows. |

**Parallel machine surface (the drift):** `scripts/hook-routing-log.sh` machine-writes
`memory/routing_log.md` (PostToolUse, serialize-with-lock append at hook-routing-log.sh:217).
This is routing/event information written as **markdown by a hook**, sitting *beside* the JSONL
store rather than being derived from it — a second machine-writer outside `pmctl`.

**Other machine-written surfaces (sidecar telemetry — classification pending, see §9 D5):**
beyond the 5-entity state model there are two more non-`pmctl` writers — `scripts/hook-save-rate-limits.sh`
→ `rate-limits.json` (CC-269 tracks moving it under the state root) and `scripts/log-usage.sh`
→ `usage-tracker.jsonl` (called from the adapter at dispatch). These are *telemetry sidecars*, not
part of Run/Task/Event/Review/Decision. Whether they must also flow through the single writer or are
explicitly exempt is **deferred to after the foundation** (D5); Phase 1 does **not** re-route them.

**Store layout** is already specified: `core/state/layout.yaml` (root
`$PM_DISPATCH_STATE_ROOT` → XDG → `~/.local/share/pm-dispatch/state`, per-project sha1 partition,
`runs.jsonl` / `events.jsonl` / `tasks/<id>.json`).

**Net:** the substrate is *defined* (schemas + FSMs + layout + a writer lib) but *mostly
unconsumed*. Only Run is produced, and via the wrong writer. This is architectural drift in the
core boundary, not polish — matches `docs/architecture/v0.3.0-synthesis.md` Conformance §B.

## 3. Target contract (single-writer)

The repo's own rule (synthesis §"state rule"): **human-authored Markdown stays Markdown;
machine-authored state is JSONL; `pmctl` is the only writer.** The foundation implements it:

1. **`pmctl` is the sole machine-state writer.** Adapters, hooks, and the gate stop writing state
   directly; they either call a `pmctl` state op or emit through a `pmctl`-owned path.
2. **Append-only event stream.** Every state-changing action (`run.dispatched`/`run.completed`/
   `run.failed`, `guard.denied`/`guard.warned`, later `task.*`/`review.*`/`decision.recorded`)
   appends one Event to `events.jsonl` via `pmctl`.
3. **Run/Task/Review/Decision are derived/written through `pmctl`**, never by an adapter.
4. **`routing_log.md` is no longer machine-written.** Routing becomes a projection of the event
   stream (decided: dropped in favour of `pmctl trace` — D3=b). Human notes in memory stay markdown.
5. **Writes are schema-validated.** `pmctl` validates every append against the matching
   `core/schema/*.schema.json` before writing. Today `sw_append_dispatch_run` builds the Run JSON
   inline (state-writer.sh:184) with **no validation**; moving the write into `pmctl` is the point to
   enforce it, so malformed state can never be appended.
6. **`pmctl --json` is the machine-output contract** (cross-cutting; synthesis §B). Phase 2 state
   ops (`pmctl task` / `pmctl trace`) emit structured JSON so consumers (and a future MCP bridge)
   read a stable interface, not scraped text.
7. **`pmctl` owns the read/query path, not just writes (D6).** The store is JSONL; `pmctl` is the
   query surface. Consumers (trace, task gate, memory v2, context-enricher) read state through
   `pmctl` — by id, by `task_id`, by event `kind`, and by time-window — never by ad-hoc grep of the
   JSONL. A single-writer without a read contract is only half a substrate.
8. **Bounded growth — rotation is implemented (D7).** `runs.jsonl` / `events.jsonl` rotate per
   `core/state/layout.yaml` (gz archive `archive/{runs,events}-$YYYYMM.jsonl.gz` at the specified
   threshold). The append-only stores must not grow unbounded; rotation ships with the foundation,
   not deferred.
9. **Canonical writes are loud (D8).** Once `pmctl` is the sole writer of load-bearing state, a
   failed Run/Event append **surfaces** (visible / non-zero on the `pmctl` path) instead of the
   current silent best-effort (`state-writer.sh` logs to `state-writer.err` and `return 0`). A
   substrate that silently drops state lies to its consumers. (Best-effort stays acceptable only for
   the sidecar telemetry surfaces under D5.)

## 4. Change seams (where the writers move)

These are the concrete edges to re-route — each is a seam, not a rewrite:

- **Adapter Run write** (`adapters/{codex,claude}/dispatch.sh` calling `sw_append_dispatch_run`):
  move the write up into `pmctl dispatch run` (`scripts/lib/pmctl-dispatch.sh`), which already owns
  validate → guard → route → invoke → post-verify. `pmctl` records Run + emits `run.*` Events from
  the adapter's stdout footer (it already parses `last:`/`stderr:`/`exit:`). Adapters go back to
  pure executor invocation + output contract (aligns with the CC-233 thin-adapter rule).
- **Guard events** (`scripts/lib/pmctl-guard.sh` / the hook guards): on deny/warn, emit
  `guard.denied`/`guard.warned` Events through `pmctl` (the guard already runs inside `pmctl guard
  check`).
- **routing_log** (`scripts/hook-routing-log.sh`): stop the markdown append; the same information is
  an Event (`run.dispatched` etc.). `pmctl trace` is the read path (D3=b). **Reader surface is small**
  — the only consumer is `install-hooks.sh` (the auto-block wiring at install-hooks.sh:364-368) plus
  the hook itself and its tests; no PM-snapshot / mem-recall path reads it — so the *reader* surface
  is small. **But** the migration itself is not free: the existing `migrate-routing-log.sh` targets
  the old markdown shape, and the hook's `kind` values aren't in the core Event enum — a real
  `routing_log → events.jsonl` migration with kind-mapping is needed (see §10.A6).
- **State writer lib** (`scripts/lib/state-writer.sh`): keep as the low-level append primitive, but
  its callers become `pmctl` only. Add the missing `events_append` wiring; `task_upsert` gets its
  first production caller from `pmctl task`.

## 5. Thin vertical slice (the first landing, timeboxed)

Prove the contract on **one** path before touching the others:

> A single `pmctl dispatch run` writes **Run + one Event (`run.dispatched`/`run.completed`)**
> through the single writer (`pmctl`, not the adapter), and `routing_log.md` is **no longer
> machine-written** for that path.

**Acceptance:**
- `pmctl dispatch run` produces the Run row in `runs.jsonl` and a matching Event in `events.jsonl`,
  both via `pmctl` (adapter no longer calls `sw_append_dispatch_run`).
- A dispatch produces **no** new machine write to `routing_log.md`.
- Existing dispatch/guard tests stay green; new tests assert the Run+Event pair and the absence of
  the adapter-side write.
- `bash scripts/run-all-tests.sh` exit 0.

**If this cannot land cleanly without broad rewrites → fall back to plan B** (minimum single-writer
decision + one DX feature), per §7. This is the cheapest early signal.

## 6. Sequencing

1. **Single-writer + event stream (CC-211 / CC-306; builds on CC-230):** the state store + a
   `routing_log.md`→`runs.jsonl` migrator already shipped (**CC-230 ✅ #159**) — but the hook still
   machine-writes the markdown (the drift in §2), so this is *completing* CC-230's intent, not
   re-doing it. §5 slice first, then extend the same pattern to the guard and routing seams. End
   state: `pmctl` is the only writer; `events.jsonl` is produced; `routing_log.md` no longer
   machine-written; CC-306 layer-enforcer extended to forbid re-introducing direct state writes
   from adapters/hooks.
2. **State ops (CC-215):** `pmctl task` / `pmctl decision add` / `pmctl trace tail`, JSON output,
   production callers for `task_upsert` + `decision` + event append. This is the load-bearing
   remainder of `pmctl` deferred from v0.3.0.
3. **First state consumer — `pmctl trace` (decided, D2=a):** read-only observability over
   `events.jsonl` (tail / filter by subject / kind), to prove the stream is real and useful at the
   smallest surface. The CC-235 task-lifecycle gate is the next consumer after trace, not first.

## 7. Risks & early signals

- **Biggest risk — and why it's accepted:** a substrate-heavy release with no user-visible payoff.
  The maintainer has **explicitly accepted** this (2026-06-03): the current user base is small, so
  there is no pressure to ship features over correctness. This downgrades the original top risk;
  the residual concern is purely the "too large for a single maintainer" failure mode that caused
  full `pmctl` to be deferred from v0.3.0 (`DECISIONS.md`).
- **Early signal to fall back:** the trigger is now **technical, not payoff-driven** — if the §5
  slice can't land without broad rewrites across adapters + hooks + gate, stop, do only the minimum
  single-writer fix, and re-time the rest. (DX wins like CC-064 remain available but are not the
  fallback's purpose, since visible payoff is no longer the gating concern.)
- **Migration risk:** turning off `routing_log.md` machine writes affects existing installs that
  read it. Needs a back-compat/migration story (§9) — `scripts/migrate-routing-log.sh` already
  exists as a precedent.

---

## 8. Explicitly NOT next

- **CC-216 MCP server** — must wrap a *stable* `pmctl`; the CLI is still maturing and `mcp/README.md`
  was never written. Building MCP now freezes an immature interface or forks a second state API.
- **CC-234 / CC-237 capability layer** — event-derived memory + context-enricher consume the event
  stream; they are castles on sand until §5–§6 land.
- **`adapters/antigravity` / `adapters/opencode`** — named slots, no demand yet.

## 9. Decisions

**Resolved 2026-06-03:**

1. **CC-211 commit — ✅ A (commit state-first).** State-first foundation is the v0.4.0 headline.
   Rationale incl. the maintainer's explicit acceptance of low short-term payoff (small user base);
   de-risked by the §5 thin slice + technical fallback. See `DECISIONS.md` 2026-06-03.
2. **First state consumer — ✅ (a) `pmctl trace`.** Cheap observability over `events.jsonl` proves
   the stream at the smallest surface; CC-235 task-lifecycle gate is the *next* consumer, not first.
   (Claude leaned a; codex leaned b — resolved to a.)
3. **`routing_log.md` disposition — ✅ (b) deprecate** in favour of `pmctl trace`; single source =
   `events.jsonl`. Needs a migration / back-compat path (precedent: `scripts/migrate-routing-log.sh`),
   to be built when the routing seam (§4) is reached.
4. **Run/Event write transactionality — design requirement (upgraded per codex audit).** Append-only
   JSONL, Run-then-Event. But "detectable partial" is not enough: the pair shares an **operation id**
   (idempotency key) and there is a **reconciliation invariant** — every terminal Run has exactly one
   terminal Event — checkable/repairable on read. See §10.A2.
5. **D6 — read/query contract — ✅ in foundation.** `pmctl` provides read ops over state (by id /
   task / kind / time-window); JSONL is the store, `pmctl` is the query surface. See §3.7.
6. **D7 — rotation — ✅ implement in foundation.** `runs`/`events` rotate to gz archives per
   `layout.yaml`; not deferred. See §3.8.
7. **D8 — write-failure posture — ✅ loud.** Canonical-state write failures surface (non-zero /
   visible on the `pmctl` path), replacing silent best-effort. Sidecar telemetry (D5) may stay
   best-effort. See §3.9.

**Open (deferred to after the foundation lands):**

8. **D5 — telemetry classification.** Do the sidecar machine-writers `rate-limits.json`
   (`hook-save-rate-limits.sh`, CC-269) and `usage-tracker.jsonl` (`log-usage.sh`) count as *state*
   (must flow through the single writer) or as *exempt telemetry sidecars*? Deferred: Phase 1 builds
   the 5-entity single-writer first and does not re-route these. Revisit once the core writer exists.

## 10. Foundation hardening (codex audit 2026-06-03)

An independent read-only codex audit found gaps beyond the write-path framing above. Folded here;
the high items are the load-bearing additions, the checklist is the robustness/security pass.

### A. High — must land with the foundation

- **A1 — VERSION gating must not downgrade.** `state_store_init` writes `1` back whenever
  `$STORE/VERSION` ≠ `1` (`scripts/lib/state-writer.sh:85-90`); an older binary touching a future v2
  store silently downgrades it. Fix: create `VERSION` only when absent; if present and unsupported,
  **fail loud** with a migration path — never rewrite it down. → CC-311.
- **A2 — Run+Event need a transactional/idempotent write API.** `runs_append`/`events_append` lock
  different files (`state-writer.sh:104-129`) with no shared operation id, idempotency key, or
  reconciliation API. Fix: a `pmctl`-owned record-dispatch op that writes the pair under one
  operation id with the invariant "every terminal Run has exactly one terminal Event". → CC-310.
- **A3 — Run recording must realize the FSM, not just terminal exit.** `run-states.yaml:15-28`
  defines `pending → dispatched → verifying → ok|partial|failed`, but adapters append one Run after
  executor exit (`adapters/codex/dispatch.sh:359-369`) and `pmctl_dispatch_run` can return before any
  write on failure/post-verify paths (`pmctl-dispatch.sh:248-263`) — a crashed `pmctl` leaves no
  in-flight Run. Fix: `pmctl` creates `pending`/`dispatched` before invoke, `verifying` after, then
  the terminal state; emit an Event per transition. → CC-310.
- **A4 — Run/Event schemas too loose for the reader.** `run.schema.json` requires only
  id/schema_version/task_id/executor/state/created_ts; `trace_path`/`working_dir`/`exit_code`/
  `finished_ts` are optional (`core/schema/run.schema.json:22-59`), and Event `payload` is entirely
  loose (`core/schema/event.schema.json:18-47`) so a reader can't tell `ok` from `partial` or
  validate `from→to`. Fix: a stricter dispatch-run shape (require trace fields) + per-`kind` payload
  contracts carrying `from_state`/`to_state`/`run_id|task_id`, validated against the FSMs on write.
  → CC-312.
- **A5 — partition identity collapses to `global`.** `repo.json` is promised
  (`core/state/layout.yaml:36-39`) but never written (`state_store_init` only mkdirs + VERSION); and
  `_sw_project_key` falls back to `global` outside git / on hash failure (`state-writer.sh:45-67`),
  mixing unrelated work and making worktree / WSL↔Windows identity unreconcilable. Fix: write
  `repo.json` on first use (git top-level, `git common-dir`, worktree path, normalized/cygpath
  aliases); **refuse `global`** for load-bearing project writes unless explicitly requested. → CC-313.
- **A6 — routing_log deprecation needs a real events migration.** The hook writes `kind`
  `bash-dispatch`/`agent-dispatch` (`scripts/hook-routing-log.sh:322-325`) which are **not** in the
  core Event enum (`event.schema.json:18-30`); the existing `migrate-routing-log.sh` only migrates the
  old markdown shape. Fix: a new `routing_log → events.jsonl` migration with explicit kind mapping +
  subject-id strategy; keep the old migrator as legacy-markdown cleanup only. (Corrects the earlier
  "low-cost deprecation" note in §4.) → CC-314.

### B. Hardening checklist (med — robustness / security / governance)

- **Writer boundary**: `_runs_append_inner`/`_events_append_inner` blindly `printf '%s\n'`
  (`state-writer.sh:96-129`) — a string with embedded newlines appends multiple rows. Reject
  newline/NUL, `jq -c`-compact, and schema-validate at the boundary. → folded into CC-309.
- **Layer-boundary test inversion**: `test-layer-boundaries.sh:20-23,161-172` currently *allows*
  adapter state logging — so the single-writer regression would still pass. Invert it (only the
  designated `pmctl` writer may call `runs_append`/`events_append`/write `$STORE`). → CC-309 / CC-306.
- **Loud writes (D8)**: canonical write failure must surface, not `return 0`. → CC-309.
- **mkdir lock stale-owner**: `serialize_with_lock`'s mkdir fallback (`portable.sh:174-180`) has no
  pid/host/trap/stale-reclaim — a killed writer on a flock-less FS blocks until timeout forever. Add
  owner metadata + cleanup trap + bounded stale reclaim + a UNC/9P preflight warning. → CC-317.
- **Rotation filename collision**: `archive/{runs,events}-$YYYYMM.jsonl.gz` (`layout.yaml:46-63`)
  collides on >1 rotation/month; add a monotonic segment suffix and define active+archive merge for
  the reader. → CC-316.
- **Read covers archives**: the read contract must define active+archive semantics (ordering,
  corrupt-row handling, time-window, indexed vs streamed) so `trace --since` can't miss archived
  state. → CC-315.
- **layout.yaml as source of truth**: it's "definitions only" while writer paths are hardcoded
  (`state-writer.sh:83-118`) — drift-prone. Either consume layout in writer/reader, or add golden
  tests comparing layout paths/locks/subdirs to writer behavior. → CC-317.
- **Store-root safety**: `_sw_store_root` trusts env directly + plain `mkdir -p` (`state-writer.sh:32-90`)
  — no canonicalization, symlink-component rejection, world-writable check, or `0700` mode. → CC-317.

### C. Corrections to the earlier (Claude) pass

- Enum parity is **not** untested — `test-core-schemas.sh:171-218` checks executor/route/task/run/
  reviewer/verdict enum sync. What's missing is **transition + per-event payload** validation (A4).
- sha1 partitioning portability was already fixed (`_portable_sha1`, tests at `test-state-store.sh:493-542`);
  the open issue is **identity semantics + the unsafe `global` fallback** (A5), not the hash itself.
