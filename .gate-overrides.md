## Gate Overrides

### Accepted risk: `Edit(/tmp/brief-*)` / `Edit(/tmp/handover-*)` scope (security-reviewer-F001)

security-reviewer flagged that migrating `Write(/tmp/brief-*)` / `Write(/tmp/handover-*)`
to `Edit(...)` grants broad, symlink-able `/tmp` write authority, since a
`Write(<path>)` permission rule never matched anything under this tool's
permission model (only `Edit(<path>)` does).

User-accepted risk, recorded explicitly rather than implemented as a
narrower per-run private directory:

- This scope is not new intent — these exact glob strings were already
  present as (inert) `Write(...)` entries in the user's own settings before
  this change; the fix makes an existing, already-approved permission rule
  actually take effect, it does not expand what was asked for.
- The glob is already the write boundary the executor-dispatch flow enforces
  independently: `runtime/hooks/guard-executor-write.sh` and
  `runtime/lib/handover-validate.sh` both hard-code `/tmp/brief-*.md` /
  `/tmp/handover-*` as the only path shape the dispatch flow will write to,
  so this permission entry is not the sole containment for that path.
- A per-run, ownership- and symlink-safe private directory (the reviewer's
  suggested alternative) is accepted as a real future improvement, not
  something to build as part of this fix. Tracked for later hardening rather
  than blocking this permission-repair change.
